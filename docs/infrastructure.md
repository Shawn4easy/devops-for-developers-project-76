актуальные адреса берутся так:

```bash
yc compute instance list
```

Внутренние адреса при этом не меняются, поэтому целевую группу балансировщика править не нужно —
только `inventory.ini`.

### Фильтрация исходящего трафика

Первый публичный адрес `app-01` (`51.250.69.112`) попадал под фильтрацию: с него не открывались
`apt.datadoghq.com`, `download.docker.com` и `github.com`, а `s3.amazonaws.com` отвечал через раз.
Блокировка была по адресу источника, не по зоне: `app-02` с теми же хостами работал нормально.

Лечится перезапуском машины — она получает новый адрес из другого диапазона:

```bash
yc compute instance stop app-01 && yc compute instance start app-01
```

После этого нужно поправить `inventory.ini`.

перевода в healthy, 3 неуспешные — в unhealthy.

## DNS

Домен `shawn4easy.ru` зарегистрирован в reg.ru и делегирован в Yandex Cloud DNS.
NS-серверы в реестре `.ru`: `ns1.yandexcloud.net`, `ns2.yandexcloud.net`.

Публичная зона `app-zone` — `dns3hq43pqimjb247geh`.

| Запись | TTL | Тип | Значение |
|---|---|---|---|
| `shawn4easy.ru.` | 300 | A | `158.160.236.3` |
| `www.shawn4easy.ru.` | 300 | A | `158.160.236.3` |
| `_acme-challenge.shawn4easy.ru.` | 300 | CNAME | `fpq3ciav0ffc5itf8c82.cm.yandexcloud.net.` |
| `_acme-challenge.www.shawn4easy.ru.` | 300 | CNAME | `fpq3ciav0ffc5itf8c82.cm.yandexcloud.net.` |

Апекс и `www` описаны двумя A-записями, а не CNAME: стандарт не разрешает CNAME
на вершине зоны, а заводить ALIAS ради учебного проекта незачем.

Низкий TTL в 300 секунд оставлен на время настройки, чтобы правки применялись
за минуты, а не за час.

Записи `_acme-challenge` — валидация Let's Encrypt. Выбран вариант с CNAME, а не
с TXT: при продлении сертификата Yandex Cloud меняет TXT на своей стороне, и
записи в нашей зоне трогать не приходится.

## Проверка

На обеих машинах запущен Redmine, балансировщик распределяет между ними запросы:

- `http://shawn4easy.ru/` → `301` на `https://shawn4easy.ru/`
- `https://shawn4easy.ru/` → `200`
- то же по `www` и по IP балансировщика

Приложение работает с общим кластером PostgreSQL, поэтому данные одинаковы
независимо от того, на какую машину попал запрос.

## Мониторинг

Агент DataDog версии 7 на обеих машинах, ставится ролью `datadog.datadog` в play подготовки
серверов. Регион организации и ключ API лежат в `group_vars/webservers/vault.yml`.

Проверка `http_check` в двух экземплярах:

| Имя | URL | Что показывает |
|---|---|---|
| `redmine-local` | `http://localhost:8080` | здоровье приложения на конкретной машине |
| `redmine-public` | `https://shawn4easy.ru` | всю цепочку: балансировщик, сертификат, маршрут |

Вторая проверка избыточна с точки зрения задания, но без неё мониторинг не заметит, что
балансировщик выкинул из ротации обе машины, пока сами машины живы.

Роль `datadog.datadog` скачивает APT-ключи через `get_url` без повторов. Связность с
`s3.amazonaws.com` нестабильна, поэтому ключи скачиваются заранее в `pre_tasks` с повторами
и собираются в связку — роль находит их готовыми и в сеть не ходит.
